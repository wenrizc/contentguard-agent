# 复盘

## 最难的问题

- 最难的是同时满足 ReAct 的动态性和业务安全边界。解决办法是让模型只选择工具，代码只校验参数、调用预算、审核证据和写入权限；工具结果通过结构化消息回到模型。
- 时间冲突不能靠字符串提示解决。最终用带时区的 `datetime`、小时候选网格和 SQLite 事务内占用复核，保留原始硬性时间并要求显式确认。
- 外部视频审核在当前考核范围内没有真实服务凭据。使用统一 `VideoModerator` 接口和带 `provider=mock`、`simulated_*` 证据来源的合成结果，避免把流程测试说成视频识别能力。

## 学习收获

- 原生 Python 的单循环足以展示 Agent 决策边界，框架并不能替代工具契约和验证材料。
- Trace 同时记录工具参数、结果摘要、后续动作和简短依据，能在不保存隐藏思维过程的前提下复盘模型行为。
- 将审核状态、任务状态、确认状态和保存状态分开，能避免“草稿已保存”被误写成“已发布”。

## 失败用例带来的修改

- pytest 脚本入口没有自动导入仓库根目录，改为在 `pyproject.toml` 中配置 pytest `pythonpath`。
- 确认后的并发占用要求保存前复核，SQLite 写入改为 `BEGIN IMMEDIATE` 并登记草稿占用区间。
- 数据库初始化失败改为延迟到 `save_status=FAILED` 返回，保证 CLI 能输出明确失败而不是崩溃。
